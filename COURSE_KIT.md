- Комплект распакован в `.course-kit/v1`.

- SHA-256 архива: `fec6b4e886c19146078bf69fbf90a19279a4cd33f656642395350b299efeb226`.
- Проверки checksum архива и всех файлов из `MANIFEST.sha256` прошли.
- Комплект, архив и checksum исключены из Git. Каталоги `build/`, `install/`, `log/` также исключены.
- `origin` настроен на `https://github.com/reev1l/ros2_nsu.git`; доступность удалённого репозитория и права проверяющего не проверялись.
- Для ПР01 подготовлены README с командами опыта, `.github/workflows/ci.yml`, декларация ИИ и фактические evidence. Автоматический опыт настоящими ROS-нодами выполнен: 62,497 Гц, разрыв в домене 17 (`exit=124`), восстановление в 16 (`exit=0`). Qt-симулятор работал без окна, клавиша отправлялась в teleop через PTY. Ручное повторение студентом пока не подтверждено.
- Полные наблюдения находятся в `evidence/pr01/graph.md`, сырые команды и результаты — в `commands.json` и `measurements.json`. Отчёт оформляется после коммита реализации; актуальный результат checker сохранён в `evidence/pr01/checker.json` после проверки.

## Перед первой сдачей

1. Выполнить опыт из [условия ПР01](https://ros.lms.ci.nsu.ru/practices/pr01) по подготовленному [README](README.md) и записать реальные результаты в evidence. По манифесту ПР01 нужны `evidence/pr01/doctor.txt`, `graph.md` и `environment.json`, а также общий `report.json`. Скрипт `workstation_report.sh` даёт дополнительный отчёт; он не заменяет эти файлы.
2. Проверить подготовленный `.github/workflows/ci.yml` полным запуском в GitHub после оформления сдачи. Для ПР01 нужны проверка JSON, загрузка зафиксированного комплекта и checker. Использовать `actions/checkout` с `fetch-depth: 0`, чтобы checker видел историю коммитов. Для этой ревизии зафиксированы:

   ```yaml
   env:
     COURSE_KIT_URL: https://ros.lms.ci.nsu.ru/downloads/robotics-course-kit-v1-w04-fec6b4e886c1.tar.gz
     COURSE_KIT_SHA256: fec6b4e886c19146078bf69fbf90a19279a4cd33f656642395350b299efeb226
   ```

   Проверять скачанный архив этим SHA-256 **до** распаковки. Загружать его во временный каталог или удалять после распаковки, чтобы посторонний untracked-архив не мешал checker. Не получать «последнюю» версию через API внутри CI и не подавлять ошибки проверок.
3. Закончить README, workflow и остальные файлы реализации. Создать коммит **A**, исключив текущий evidence и `AI_USAGE.md`. Все инструкции и изменения `.gitignore` тоже должны войти в A: после него checker разрешает изменения только в evidence текущей ПР и декларации ИИ.
4. Скопировать `practices/templates/report.json` в `evidence/pr01/report.json`, если отчёта ещё нет. Заполнить все `replace-with-*`, номер работы, SHA(A), версию комплекта и SHA-256 архива, реальные команды, тесты, дефект и его исправление, часы из условия и claims из манифеста. Не заявлять успешные проверки, которые не выполнялись.
5. Создать `AI_USAGE.md` из шаблона, если его ещё нет, и заполнить раздел `PR01`. ИИ уже помогал с проверкой комплекта и этой инструкцией: если подготовка используется в ПР01, указать её в декларации и поставить `ai_used: true`. Указать модель GPT-6, среду Codex, характер помощи и способ самостоятельной проверки. При следующих ПР добавлять разделы, сохраняя предыдущие.
6. Проверить JSON и evidence:

   ```bash
   python3 -m json.tool evidence/pr01/environment.json > /dev/null
   python3 .course-kit/v1/tools/check_practice.py PR01 --submission .
   ```

7. После успешной проверки создать коммит **B**, содержащий только `evidence/pr01/` и `AI_USAGE.md`; в `report.json` оставить SHA(A). Отправить B в GitHub, дождаться успешного CI именно для B и сдать ссылку на репозиторий, полный SHA(B) и ссылку на его CI run.

## Для следующих работ

- В начале новой работы проверить текущую ревизию: `curl -fsS https://ros.lms.ci.nsu.ru/api/course-kit`. Ответ даёт `version`, `archive`, `checksum`, `sha256`; относительные URL дополнить `https://ros.lms.ci.nsu.ru`.
- Если появилась новая неделя, скачать архив и checksum, проверить SHA-256 и распаковать поверх `.course-kit/`. Затем проверить внутренний манифест. Использовать одну ревизию локально, в отчёте и CI; перенести immutable URL и digest новой работы в workflow.
- Уже принятое evidence не переписывать. Для повторения старой сдачи использовать её зафиксированную ревизию, а для новой работы или официальной пересдачи — выбранную новую ревизию.
- Создавать `evidence/prNN/report.json` и добавлять раздел `PRNN` в `AI_USAGE.md`; брать файлы и claims из соответствующего манифеста. Не перезаписывать готовый отчёт шаблоном.
- В ПР02 добавить сборку `turtle_bringup` и проверку установки launch-файла по условию. С ПР03 перед checker выполнять сборку и функциональные тесты:

  ```bash
  colcon build --symlink-install
  colcon test --event-handlers console_direct+
  colcon test-result --verbose
  python3 .course-kit/v1/tools/check_practice.py PR03 --submission .
  ```

  Заменять `PR03` номером текущей работы. Checker проверяет оформление evidence и историю Git; поведение ROS подтверждают команды опыта и тесты пакетов.
- Если менялись код, README, CI или другие файлы реализации, создавать новый A, повторять затронутые проверки и обновлять `report.commit` перед новым B. Если менялось только evidence текущей работы или декларация, SHA(A) оставлять.

Повторная проверка целостности из корня репозитория:

```bash
sha256sum -c robotics-course-kit-v1.tar.gz.sha256.txt
(cd .course-kit/v1 && sha256sum -c MANIFEST.sha256)
```
